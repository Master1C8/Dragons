# Windows UI and settings composition

`localization/windows_ui_locale.py` SHA-256 `9ecec064cf154be33f563d811f5781c37d5b199a575e3dccf196f43e98bc6653`, together with `localization/windows_settings_locale.py` SHA-256 `5a61aa0b6e7e8f4a207640f6c284a824fba9da2232e79eaf861fe6a5620d0cf9`, can build `sharedassets0.assets` with UI strings and source-bound settings labels/options in one separately published file. It checks the original build, asset and managed schema inputs, all known settings classes, unbound localization references and no-op source serialization. Resolution option values and empty settings fields are excluded from editable inputs as preserve-exactly; these provisional field classifications do not establish that every remaining candidate is suitable for translation. It verifies every output object's expected raw bytes and decodes modified settings objects before publishing the file. A UI locale can be omitted when producing settings alone; similarly a Yarn locale can be used alone for `sharedassets1.assets`. Dialogue and settings live in different assets and are not one transaction.

The `test_windows_ui_locale.py` suite SHA-256 `09c995bde8657a07de7a733370a21770d882038a3b1ff709df0bffff08430236` contains 17 focused tests. A combined UI/settings positive control independently verified that only the intended two serialized objects changed, checked actual decoded label and option values and confirmed the resolution object stayed byte-identical. A separate settings-only control changed three different setting classes in one output. Other controls cover settings-only and dialogue-only input, missing input, wrong asset, mismatched locale, a forbidden resolution value, stale dialogue, and failures after temporary serialization but before publication. A forced settings decode failure removed the newly created temporary file and published neither change. The complete suite passed 80 tests. This is an individual-file safety boundary; a crash may leave a temporary file and no multi-file install/rollback is claimed.
