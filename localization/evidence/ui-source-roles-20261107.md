# Provisional serialized UI source roles

`classify_ui_sources.py` uses the source-pinned TMP hierarchy scan and cross-build pairing to assign a provisional role to every known serialized UI object. It binds each role to the asset, complete hierarchy, per-build ID and source-text SHA-256. The report `ui-source-roles-20261107.json` contains 162 paired hierarchy records: 138 have macOS fields and all 162 have Windows fields. The extra 24 are the Windows pause-menu fields in six scenes. Every macOS field has a same-path Windows counterpart with an equal source-text hash. This is coverage of the known nine serialized UI assets, not proof that all game text has been discovered.

The paired records comprise 36 credit-description candidates and 34 credit-name preservation candidates; 15 dialogue presenter templates and one dialogue option template; 12 other menu-text candidates and 24 Windows pause-menu candidates; six gameplay indicators, six cheat-menu fields, one ending-text candidate, 11 settings-prefab fields, seven version-display fields, six dynamically populated slot-progress fields and three normal new-slot labels. The JSON retains each occurrence separately even when texts are identical. Roles are provisional: author names and attribution titles require editorial review, including `GDC Bundle Part 4`, and no automatic translation or exclusion is implied. A runtime-replaced field may still appear before replacement or in an untested state.

The classifications are based on serialized hierarchy and previously traced selected consumers, not runtime visibility, reachability, a complete preserve-exact contract or final editorial decisions. Settings-prefab, dialogue-presenter and version-display consumers remain explicitly marked needs-review; cheat visibility is unresolved. Text baked into textures is excluded by the owner's instruction. Other text sources and final UI scope remain open.

The report was regenerated byte-for-byte from both pinned builds. Tests check the exact per-build counts, representative delete confirmation, dynamic slot and normal slot roles, and rejection of an unknown hierarchy. ## Builder enforcement, 2026-11-10

The shared role mapping now feeds the inventory, both normal UI builders,
the macOS settings merge and the combined-asset verifiers. The builders
check the role report fingerprint and each protected source value by
platform and object ID before replacing text. This covers the four
audited template groups (39 paired fields) and retains the existing
34 contributor-name checks.

The regression tests use both actual source builds. Each adapter rejects
a changed value in each template group at the preservation guard, before
publishing output. Exact template values remain accepted. The settings
composition tests verify that the setting changes while the adjacent
template object stays byte-identical. Separate corruption and read-back
controls still reject changed objects and leave candidate bytes intact.

The refactored inventory assembly reproduces v37 byte-for-byte. This
enforces the audited UI roles and leaves the broader shared inventory and
non-UI preservation work open.
