# Windows TMP UI asset adapter

The initial adapter at commit `1b2d15c`, `localization/windows_ui_locale.py` SHA-256 `145698a4b98bab7dbf71a6114ddec10da0ccd2aa59e277765eabe85bf86caf27`, built a separate Windows UI asset from a locale file for any of the nine pinned `level0`–`level6`, `sharedassets0.assets` or `sharedassets1.assets` sources. It checks the Windows build, global scripts and asset bytes before decoding `TMPro.TextMeshProUGUI` fields, requires exact source values and a matching locale, and verifies every serialized object's raw data after writing. Output must be a fresh path outside the installed game directory. It reserves a separate temporary file, verifies it and links it to the final name only after successful read-back; ordinary failures clean up the temporary file, while an already existing temporary or final file is preserved. This is an individual asset boundary, not a transaction across multiple files or an installer. A crash can leave a temporary file.

The adapter does not establish whether every candidate field should be translated. Source classification, code-generated strings, settings, dialogue composition, font behavior, the other platforms, complete package integration and final runtime verification remain separate and incomplete. At that checkpoint it started from an original asset and did not merge dialogue or settings changes. The later dialogue-composition extension is documented in `windows-ui-dialogue-composition-20261107.md`; settings composition and a Windows release builder remain open. The texture-text exclusion remains in force.
