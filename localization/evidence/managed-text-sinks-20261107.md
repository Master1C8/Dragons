# Managed text setter and dropdown discovery

The source-pinned scanner `tools/text-setter-consumers` parses every root managed
DLL in each installed build. It records direct `call`/`callvirt` instructions to
any one-string `set_text` method, their preceding four instructions, direct
`TMP_DefaultControls`/`DefaultControls` factory calls, and selected TMP dropdown
field and multi-select setter references. The 170 macOS and 172 Windows assemblies
are bound to their complete sorted name/hash inventory and the exact Mono.Cecil
binary. Each build has 249 such setter calls, of which 11 are in
`Assembly-CSharp.dll`: six save-slot format calls, three direct `NEW` assignments,
one `Objective.GetName` assignment, and one `Application.version` assignment.
The four-instruction window is a discovery aid, not a general dataflow proof.

Both builds' Unity DLLs contain potentially displayed defaults, including
`Button`, `Enter text...`, `Option A/B/C` and the TMP multi-select options
`Nothing`, `Everything`, and `Mixed...`. The scan found 58 direct calls to
the selected default-control factory methods in each build, all within
`Unity.TextMeshPro.dll` or `UnityEngine.UI.dll`. This does not rule out
indirect invocation, runtime creation, additional code or an already serialized
prefab. Do not exclude the defaults from the shared inventory solely on this
observation. The eight selected TMP multi-select option-field references are
inside `TMP_Dropdown`: initialization and uses in `RefreshShownValue` and
`Show`. The scanned root managed DLLs contain no direct method reference to
`TMP_Dropdown.set_MultiSelect`; the field write within that setter is a positive
control. Reflection and dynamically loaded code remain possible.

`inventory_tmp_dropdowns.py` independently scanned the 17 source-pinned
serialized assets per build, with all script identities resolved and no-op
byte checks for every selected object. It found one `TMP_Dropdown` per build:
macOS `sharedassets0.assets#672`, Windows `sharedassets0.assets#667`. Each has
serialized `m_MultiSelect` false and an empty option list at serialization.
Runtime code can populate options or alter the mode; these initial values do not
prove actual visible options or rule out additional dynamic components. The
default labels remain needs-review until their runtime scope is established.

Focused tests verify both real sources, selected known calls and serialized
objects, and reject the wrong managed inventory at the intended guard. These
static checks do not establish visibility, full source coverage, runtime
behavior, semantic classification, or an exact-preservation manifest.

Reproduce with the pinned project Python dependencies and .NET 8 / Mono.Cecil
0.11.6: build `tools/text-setter-consumers/text-setter-consumers.csproj` with
fresh work-local intermediate/output paths, then run its DLL with
`macos|windows ORIGINAL_DATA/Managed`. Run `inventory_tmp_dropdowns.py`
with `macos|windows ORIGINAL_DATA`. Tests are in
`test_tmp_dropdown_inventory.py`. Neither script modifies the original game.
